## Contexto

El usuario solicitó una aplicación web para calcular probabilidades de encontrar cartas específicas en Digimon TCG. La aplicación debe:
- Soportar configuración de mazos de 50 cartas
- Implementar 4 métodos de búsqueda diferentes (Training, Memory, Specific Search, Plain Draw)
- Permitir seguimiento en tiempo real durante partidas
- Usar Angular con SCSS y metodología BEM
- Calcular probabilidades precisas con distribución hipergeométrica

### 3. Servicios (`/src/app/services/`)

#### `probability.service.ts` (280+ líneas)
**Funciones matemáticas:**
- `factorial(n)`: Cálculo de factorial
- `binomialCoefficient(n, k)`: Coeficiente binomial C(n,k)
- `hypergeometric(N, K, n, k)`: Distribución hipergeométrica
- `probabilityAtLeastOne(N, K, n)`: P(X ≥ 1)

**Métodos de cálculo:**
- `calculateTraining()`: 2 cartas por color
- `calculateMemory()`: 3-4 cartas por tipo/color
- `calculateSpecificSearch()`: Cartas seleccionadas
- `calculatePlainDraw()`: Robo normal
- `calculate()`: Método genérico dispatcher

**Características:**
- Optimización: usa C(n, k) = C(n, n-k) para eficiencia
- Genera breakdown detallado de probabilidades
- Calcula distribución completa (0, 1, 2+ cartas)

#### `deck-state.service.ts` (295+ líneas)
**Estado reactivo:**
- BehaviorSubject<DeckState> para gestión de estado
- Observable deckState$ para suscripciones

**Métodos CRUD:**
- `initializeDeck(cards)`: Inicializar mazo
- `addCard(card)`: Agregar carta (merge si existe)
- `updateCard(cardId, updates)`: Actualizar carta
- `deleteCard(cardId)`: Eliminar carta
- `removeCards(cardId, quantity)`: Marcar como vista
- `restoreCards(cardId, quantity)`: Devolver al mazo
- `undoLastRemoval()`: Deshacer última acción
- `resetDeck()`: Resetear a estado inicial
- `clearDeck()`: Limpiar completamente

**Utilidades:**
- `getCurrentDeckSize()`: Tamaño actual
- `getAvailableCards()`: Cartas con remaining > 0
- `getCardsByCategory()`: Filtrar por categoría

**Persistencia:**
- Auto-guardado en LocalStorage después de cada cambio
- Carga automática al inicializar servicio

#### `storage.service.ts` (55 líneas)
- `saveDeckConfiguration()`: Guardar en LocalStorage
- `loadDeckConfiguration()`: Cargar desde LocalStorage
- `clearDeckConfiguration()`: Limpiar storage
- `hasSavedConfiguration()`: Verificar existencia

## Decisiones Técnicas

### 1. Distribución Hipergeométrica vs Simulación
**Decisión:** Usar fórmula matemática exacta  
**Razón:** Precisión absoluta, cálculo instantáneo, sin variabilidad  
**Alternativas consideradas:** Monte Carlo (rechazada por ser aproximada)

### 2. RxJS BehaviorSubject vs NgRx
**Decisión:** BehaviorSubject simple  
**Razón:** Suficiente para este alcance, menos overhead  
**Cuando migrar:** Si se agregan >5 features que modifican estado

### 3. LocalStorage vs Backend
**Decisión:** LocalStorage solamente  
**Razón:** Offline-first, juego personal, sin necesidad de compartir  
**Alternativas:** IndexedDB si se necesita más espacio

### 4. BEM vs CSS Modules vs Styled Components
**Decisión:** BEM stricto  
**Razón:** Solicitado explícitamente, mantenibilidad, sin dependencias extra

### 5. Componentes Standalone vs NgModule
**Decisión:** NgModule tradicional  
**Razón:** Angular CLI 16 genera así por defecto, migración futura posible

### 6. Formularios Reactivos vs Template-driven
**Decisión:** Reactive Forms  
**Razón:** Validación compleja, testing más fácil, mejor para escalabilidad

## Problemas Encontrados

### 1. Node.js Version Incompatibility
**Problema:** Angular CLI más reciente requiere Node 20+  
**Solución:** Instalado Angular CLI 16 compatible con Node 18  
**Comando:** `npm install -g @angular/cli@16`

### 2. Replace en app.component.html
**Problema:** Archivo generado con 483 líneas de placeholder  
**Solución:** Usado PowerShell para escribir contenido completo nuevo  
**Aprendizaje:** Para reemplazos totales, mejor usar Set-Content

### 3. TypeScript strictPropertyInitialization
**Problema:** Propiedades no inicializadas en algunos componentes  
**Solución:** Usar `!` assertion o inicializar en constructor  
**Decisión:** Inicializar en ngOnInit con valores default

### 4. Multiple matches en multi_replace_string_in_file
**Problema:** Patrón `deckStateSubject.next` aparece múltiples veces  
**Solución:** Agregar más contexto específico para cada reemplazo  
**Aprendizaje:** Incluir 5+ líneas de contexto para strings repetidos
